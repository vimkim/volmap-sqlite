# 05: Navigate the freelist

**What to build:** Let an operator navigate the main-file freelist from database-header evidence through trunk and leaf page claims, retaining useful prefixes and diagnostics when allocation metadata is damaged.

**Blocked by:** 03: Inspect B-tree pages and structural cells

**Status:** done

- [x] The database-header first-trunk pointer and declared freelist count are represented as physical evidence and relationship claims.
- [x] Freelist trunk pages expose their next-trunk claim and bounded leaf-page claims only after prerequisite bounds checks succeed.
- [x] Valid trunk and leaf claims resolve to distinct evidence-backed page roles and are navigable from database to trunk to leaf.
- [x] The implementation observes SQLite's freelist capacity and compatibility rules rather than reading unused entries as authoritative claims.
- [x] Out-of-range entries, impossible counts, cycles, repeated claims, truncation, and disagreement with the declared total produce contained diagnostics while retaining the validated prefix.
- [x] Freelist pages remain visible in the page atlas with allocation-specific cues and a focused entry point to the validated chain.
- [x] Empty freelists and databases with multiple trunk pages are represented without special-case UI failure.
- [x] Valid and damaged fixtures assert physical coordinates, role claims, relationships, diagnostics, and coverage through the shared inspection graph.


## Answer

Implemented header and trunk physical evidence, bounded declared leaf arrays,
allocation roles, normalized relationships, validated trunk prefixes, structured
conflict/damage diagnostics, and independent freelist coverage. The atlas provides
allocation colors, a freelist entry point, trunk-prefix navigation, focused counts,
byte regions, and bidirectional links. Stale freed-page contents do not authorize
B-tree traversal. Independently supported B-tree/overflow and allocation claims are
retained as conflicts. Sparse page overrides avoid copying the cell inventory.

Implementation: `src/inspection/freelist.rs`, shared topology/session integration,
and `frontend/src/Freelist.tsx`. Regression coverage: `tests/freelist.rs` and browser
interaction tests, including a database generated by SQLite with multiple trunks.
